# 몬스터 스폰 시스템 — 크레딧 수급 · 코스트 구매

몬스터 스폰을 "초당 몇 마리"가 아닌 **"초당 얼마의 위협 예산"** 으로 정의한 시스템입니다.
스테이지는 매초 크레딧(예산)을 수급하고, 몬스터마다 위협도에 비례한 코스트(가격)가 붙어 있으며,
스포너는 가중치 추첨으로 뽑은 몬스터를 크레딧으로 구매해 화면에 내보냅니다.
조합을 어떻게 바꿔도 총 위협량이 예산에 고정되므로, 난이도(예산 커브) · 조합(가중치 커브) · 개체 가치(코스트)를
서로 간섭 없이 독립적으로 튜닝할 수 있습니다.

> 본 폴더는 실제 프로젝트에서 발췌한 소스로, 단독 컴파일 대상이 아닙니다.  
> 파일 상단에 `※ 발췌본` 표기가 있는 파일은 스폰 시스템과 무관한 부분을 생략한 것입니다.

## 읽는 순서

| 순서 | 파일 | 형태 | 내용 |
|---|---|---|---|
| 1 | `EnemyRosterEntry.cs` | 전체 | 몬스터별 코스트 + 가중치 커브 (튜닝 축 ②③) |
| 2 | `StageThemeData.cs` | 발췌 | 테마별 크레딧 수급 커브 (튜닝 축 ①) + 로스터 |
| 3 | `StageThemeSettings.cs` | 발췌 | 전역 튜닝값 (방출 여유 배수 · 프레임당 상한), 로컬 스테이지 계산 |
| 4 | `EnemySpawnTable.cs` | 전체 | 스테이지별 가중치 평가, 가중치 추첨, 가중평균 코스트 |
| 5 | `EnemySpawner.cs` | 전체 | **핵심** — 고정 틱 수급 · 예약 구매 · 2층 방출 |
| 6 | `StageManager.Spawning.cs` | 발췌 | 배선과 수명주기 — 언제 무엇이 갱신되는가 |

## 실행 흐름

```
[StageManager — 갱신 시점]
  테마 전환      ──▶ EnemySpawnTable.Rebuild()      : 로스터 캐싱 (guid → EnemyData 해석)
  스테이지 전환  ──▶ EnemySpawnTable.ApplyStage()    : 가중치 커브 평가, 가중평균 코스트 계산
                └─▶ EnemySpawner.ApplyCreditRate()  : 수급률 적용, 방출률 파생
  Playing 진입   ──▶ EnemySpawner.StartSpawning()
  사망·클리어    ──▶ EnemySpawner.StopSpawning()

[EnemySpawner.Update — 매 프레임]
  0.25초 고정 틱 ──▶ 크레딧 적립 ──▶ PurchaseEnemies()     : 가중치 추첨 → 예약 → 코스트 지불 → 구매 큐
  매 프레임      ─────────────────▶ SpawnQueuedEnemies()  : 시간 기준 방출 + 프레임당 상한 → 화면 스폰
```

## 핵심 포인트 위치

- **예약 구매** — `EnemySpawner.PurchaseEnemies()`
  뽑힌 몬스터를 못 사면 버리지 않고 예약을 유지합니다. 매 틱 재추첨하는 단순 구현은
  비싼 몬스터를 체계적으로 걸러내는 저가 편향을 만드는데, 예약은 "실제 등장률 = 설계 가중치"를 보장합니다.
- **파생 방출률** — `EnemySpawner.ApplyCreditRate()`
  방출 속도는 별도 튜닝값이 아니라 `수급률 ÷ 가중평균 코스트 × 여유 배수`로 자동 파생됩니다.
  항상 구매보다 빨라 평상시 큐가 쌓이지 않습니다.
- **2층 방출 제한** — `EnemySpawner.SpawnQueuedEnemies()`
  1층(시간 기준 적립)은 게임플레이 페이싱, 2층(프레임당 상한)은 인스턴스화 성능 예산.
  저축 후 버스트도 손실 없이 여러 프레임으로 스무딩됩니다.
- **난이도 배율 불변식** — `EnemySpawner.Update()`
  난이도 배율을 수급·방출 양쪽에 곱해 "방출 = 구매 × 여유 배수" 관계가 배율 변화에도 유지됩니다.
